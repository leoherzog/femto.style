Migrating from Pico

Moving a site from Pico CSS 2.1.1 to femto 3.0 changes file names, class and custom property names, builds, Sass settings, color schemes and supported browsers.

femto 3.0 is derived from Pico CSS 2.1.1, copyright 2019-2024 Pico, under the MIT License (see LICENSE.md). It keeps every element and feature of Pico's default build, its 20 theme colors, its options and its color utilities, rewritten as plain CSS with femto names.

New file names and URLs

Pico 2.1.1 femto 3.0
npm @picocss/pico npm @leoherzog/femto
Composer picocss/pico None; use npm, a CDN or the download
css/pico.min.css, css/pico.css dist/femto.min.css, dist/femto.css
css/pico.colors.min.css, css/pico.colors.css dist/femto.colors.min.css, dist/femto.colors.css
css/pico.<color>.min.css dist/femto.min.css, then css/themes/<color>.css
The classless and fluid classless builds, with or without a color dist/femto.min.css, plus a theme file for a color; see Dropped builds below
The conditional builds None; see Dropped builds below

The one-file builds moved from css/ to dist/, and css/femto.css is now the @import entry. On jsDelivr, this link:

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@picocss/pico@2/css/pico.min.css">

becomes:

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@leoherzog/femto@3/dist/femto.min.css">

A themed build such as pico.jade.min.css becomes femto plus css/themes/jade.css, as two <link> tags or one combine URL:

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@leoherzog/femto@3/dist/femto.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@leoherzog/femto@3/css/themes/jade.css">

Find and replace

Replace pico with femto in class names and custom properties, in your HTML, CSS and scripts. femto has no --pico-* aliases, so every name needs the change:

  • Custom properties: --pico-primary becomes --femto-primary, and every other --pico- name likewise.
  • Color utility classes: .pico-color-jade-500 becomes .femto-color-jade-500, and .pico-background-* becomes .femto-background-*.

Change file paths, URLs and package names by the table above, not by find and replace. Data attributes keep their names: data-theme, data-tooltip and data-placement.

Dropped builds

  • The conditional builds (pico.conditional*.css), which styled only what is inside .pico, are gone. femto styles the whole page, or a shadow root that loads it (see Shadow roots). Remove the .pico classes.
  • The classless builds (pico.classless*.css and pico.fluid.classless*.css), which made the page's header, main and footer containers on their own, are gone. Load femto and give those three a container class: .container for centered widths, or .container-fluid for the full width (see Container).

Sass settings

femto has no Sass. Each Pico 2.1.1 setting is now a file, a custom property, or gone:

Pico 2.1.1 femto 3.0
$theme-color css/themes/<color>.css, after femto. Azure is built in. See Themes.
$enable-responsive-spacings: true css/options/responsive-spacings.css
$enable-responsive-typography: false css/options/fixed-typography.css
$enable-transitions: false css/options/no-transitions.css
$modules A custom module set
$breakpoints Fixed at 576, 768, 1024, 1280 and 1536px
$css-var-prefix Gone: always --femto-
$semantic-root-element Gone: always body
$enable-semantic-container, $enable-viewport Gone with the classless builds: use .container, or .container-fluid where $enable-viewport was false
$enable-classes Gone: classes are always on
$enable-important Gone: femto keeps the default build's !important declarations
$parent-selector Gone with the conditional builds
pico.colors settings Gone: femto.colors.css is a static file

Any other change is a custom property override on :root, after femto, such as :root { --femto-border-radius: 0; } (see CSS variables). Sass palette variables such as $azure-550 are custom properties in femto.colors.css, such as var(--femto-color-azure-550) (see Colors).

If your project still builds with Sass, @use "pkg:@leoherzog/femto"; includes dist/femto.min.css. Do not @use css/femto.css: Sass leaves its @imports as they are, and they would not resolve from your output file.

Color scheme changes

Color tokens are now declared once, and data-theme sets the scheme instead of redeclaring the color tokens (see Color schemes). That changes five things:

  • data-theme on a button, heading or form field keeps that element's own colors in the chosen scheme. In Pico 2.1.1 such an element took the page's background and text colors: on a dark page, <button data-theme="light"> was a white box that turned blue on hover.
  • data-theme="dark" on a web component's host now makes its shadow root dark when the component loads femto there (see Shadow roots). Pico 2.1.1, loaded only in the shadow root, gave it no color tokens.
  • Custom color overrides now work on plain :root and reach inside data-theme elements. In Pico 2.1.1, the light and automatic dark scheme selectors outranked :root, and every nested data-theme element redeclared the tokens. Likewise, your rules that set --femto-form-element-focus-color on a checkbox or radio take effect from specificity (0,1,1), where Pico 2.1.1 needed (0,2,1) or (0,3,1). To give a token a value per scheme, set its new --femto-light-* and --femto-dark-* pair on :root, such as --femto-light-primary and --femto-dark-primary (see CSS variables).
  • A color-scheme set on an element without data-theme now switches femto's colors in that subtree.
  • For a color token declared with light-dark() or set from one with var(), such as --femto-primary, getPropertyValue() now returns light-dark(...) text, where Pico 2.1.1 returned a color. To read the color in effect, see CSS variables.

Supported browsers

Pico 2.1.1 supported every browser in browserslist's defaults. femto 3.0 supports the browsers in Browser support, and drops the -ms- rules, ::-webkit-input-placeholder and ::-moz-list-bullet. Browsers without light-dark() get only femto's light scheme and are not tested, so stay on Pico 2.1.1 if you need full support in them.

Other changes

  • In Firefox, elements that set no outline of their own, such as video and tooltips with tabindex, show the keyboard focus ring again, and a field the user has left invalid shows the focus and aria-invalid rings, as in Chrome and Safari. femto drops 2.1.1's :-moz-focusring { outline: none } and :-moz-ui-invalid { box-shadow: none }.
  • Some rendering bugs of 2.1.1 are fixed, such as an indeterminate <progress> that looked complete in Firefox with reduced motion. The changelog lists them.
  • The focus ring of role="group" and role="search" inside a data-theme element follows that element's scheme.
  • With no-transitions.css, --femto-transition is 0s (2.1.1 kept 0.2s ease-in-out; see Options), so your own rules that read it stop animating too, and the group focus ring no longer fades.
  • Two other new tokens: --femto-grid-template-columns (see Grid) and --femto-primary-inverse-filter (see Themes).
  • If you used a classless build, classes such as .grid, .secondary, .dropdown and .striped that it ignored are now styled.

Every difference from Pico 2.1.1 that the parity tests found is registered, with its reason, in tests/divergences/, and the changelog lists the changes in each release.
