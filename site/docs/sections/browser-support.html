Getting started

Browser support

femto targets Baseline Widely Available on its release date: Chrome and Edge 125, Firefox 128, Safari 17.5 and Samsung Internet 27.

Its release date is no earlier than 2026-11-13, when light-dark() becomes Widely Available. The minimum versions are:

Browser Minimum version
Chrome and Edge 125
Firefox 128
Safari, macOS and iOS 17.5
Samsung Internet 27

Each minimum version is at or above what Baseline Widely Available maps to on 2026-11-13, Safari 17.5 being the first Safari with light-dark(). femto's parity tests run in recent Chrome, Firefox and Safari, not in these versions.

Prefixed and ignored features

A few features femto uses are missing or partial in some of these versions, and each is either covered by a vendor-prefixed form or ignored harmlessly:

  • Safari 17.5 reads backdrop-filter and user-select only with their -webkit- prefix, and iOS Safari reads text-size-adjust only that way.
  • Browsers that lack resize, ::selection, the ui-monospace font or some cursor keywords ignore them.
  • accent-color, partial in some, has no visible effect on femto's own controls.

femto also has vendor-only rules, such as -webkit-tap-highlight-color, @-moz-document and the ::-webkit- and ::-moz- form control pseudo-elements, which other browsers ignore.

How femto checks its CSS

In femto's repository, npm run lint runs the use-baseline rule of @eslint/css over every file in css/, with the Baseline data of web-features 3.42.0 from October 2026. It checks property names, at-rule names, @media features, pseudo-classes and pseudo-elements, and the keywords, functions and units of ordinary declarations.

It does not check custom property values, which is where light-dark() and the font stacks live, values nested inside other functions, vendor-prefixed names or browser versions. Its exceptions are listed and explained in eslint.config.mjs.

Older browsers

Browsers without light-dark(), which means Chrome and Edge before 123, Firefox before 120, Safari before 17.5 and Samsung Internet before 27, do not get a plainer femto: they get a broken one. Every color token whose light and dark values differ fails where it is used, so form fields lose their borders and backgrounds and some button labels disappear.

Tools that rewrite light-dark() for those browsers cause a narrower break in supported ones: data-theme on an element stops changing its colors. To keep a bundler from doing that, set its CSS targets as Quick start shows under npm.
