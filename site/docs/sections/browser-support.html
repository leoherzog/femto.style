Browser support

femto targets Baseline Widely Available on its release date: Chrome and Edge 125, Firefox 128, Safari 17.5, and Samsung Internet 27.

Its release date is no earlier than 2026-11-13, when light-dark() becomes Widely Available. The minimum versions are:

Browser Minimum version
Chrome and Edge 125
Firefox 128
Safari, macOS and iOS 17.5
Samsung Internet 27

Each is at or above what Baseline Widely Available maps to on 2026-11-13; Safari 17.5 is the first Safari with light-dark(). femto is tested in recent Chrome, Firefox, and Safari, not in these versions.

Prefixed and ignored features

A few features femto uses are missing or partial in some of these versions, and each is either covered by a vendor-prefixed form or ignored harmlessly:

  • Safari 17.5 reads backdrop-filter and user-select only with their -webkit- prefix, and iOS Safari reads text-size-adjust only that way.
  • Browsers that lack resize, ::selection, the ui-monospace font, forced-color-adjust, overscroll-behavior, or some cursor keywords ignore them.
  • accent-color, partial in some, has no visible effect on femto's own controls.

femto also has vendor-only rules, such as -webkit-tap-highlight-color and the ::-webkit- and ::-moz- form control pseudo-elements, which other browsers ignore.

How femto checks its CSS

femto's lint (npm run lint) checks every file in css/ against Baseline, with the use-baseline rule of @eslint/css and web-features 3.42.0 (October 2026). It does not check custom property values, where light-dark() and the font stacks live, values nested inside other functions, vendor-prefixed names, or browser versions. Its exceptions are explained in eslint.config.mjs.

Older browsers

Browsers without light-dark() (Chrome and Edge before 123, Firefox before 120, Safari before 17.5, and Samsung Internet before 27) get femto's light scheme only. They ignore a dark system setting and data-theme="dark", on the page, on an element, or on a shadow host, and the browser's own controls stay light unless your own CSS sets color-scheme: dark, which femto's colors do not follow there.

Themes, plain overrides, and --femto-light-* overrides apply in them, but an override of your own written with light-dark() fails where it is used (see CSS variables). These browsers are below femto's minimum versions, and femto is not tested in them.

Tools that rewrite light-dark() for those browsers cause a narrower break in supported ones: data-theme on an element stops changing its colors. To keep a bundler from doing that, set its CSS targets as Quick start shows under npm.
