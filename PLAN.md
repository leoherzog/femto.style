# femto.style

The conversion from Remix is finished. Its record (the phases, the parity harness, the divergence registry, the research and PROMPT.md) is at tag `conversion-final`.

This file is the site's spec: the decisions, the file tree, the URLs, the rules, the acceptance criteria the checks hold, the live risks and the owner's answers. The checks are in `tests/` ([tests/README.md](tests/README.md)).

## Decisions

Decisions 1 to 9 are the owner's, made on 2026-10-30, and the owner approved 10 to 15 the same day. Decision 16 is the owner's of 2026-11-01, 17 of 2026-11-05 and 18 of 2026-11-06. The owner changed Decision 11 on 2026-11-06 and 2026-11-09, and Decision 4 on 2026-11-09. On 2026-11-09 Decisions 17 and 18's lists of the homepage's glyphs were brought up to the reordered features, which changes nothing they decide. Decisions 6 and 15 are historical: they governed the conversion. Do not reopen any of them without asking the owner.

The `<code>` stands in for an icon feature femto may take up later; femto is not changed (the owner, 2026-11-06). |

## Rules

- **Build.** `<!-- include partials/<file> -->` markers are the only include syntax. `{{title}}`, `{{description}}`, `{{version}}` and `{{commit}}` are the only placeholders. The build fills `{{version}}` and `{{commit}}` from `site/vendor/femto/SOURCE`, so links to femto's files follow a re-vendor. Code blocks hold escaped text only, in `<code class="language-…">`, which the build highlights with Prism as one span per run of one color, classed `tag`, `attr`, `value` or `comment` (`code.css`), with plain text, most punctuation among it, left unwrapped; `picker.js`, `docs.js` and `demo.js` write the same format. The build ends each docs section with its "Edit this section on GitHub" link, written from its id, and fails on a section file that holds one.
- **Markup.** Plain `<a>` links. External links keep `target="_blank" rel="noopener noreferrer"`. The build writes `aria-current="page"` on header and footer links for the page's own path. Ids follow Decisions 7 and 13, icons Decisions 17 and 18. The docs breadcrumb reads "Documentation > <category> > <section>", and its Documentation button holds ☰ and a `<span>` label, which docs.css hides visually below 576 px, so the button keeps its name; below 360 px the category is left out.
- **JavaScript.** ES modules with `type="module"`. A widget finds its markup by a `data-` hook on its root, named after what it is and never after an attribute femto's own CSS or JS uses (`data-theme`, `data-tooltip`, `data-placement`), and does nothing when its markup is absent. No global state shared between widgets. One modal helper per dialog. Both dialogs, Modal's demo and the Colors section's color dialog, are true modals (`createModal()`, which always uses `showModal()`): the page behind is inert, and closing returns focus to the opener (the color dialog's to the swatch of the color it shows last). The page's one copy status region (`site.js` `announceCopy()`) says "Copied" at every copy and empties 1 s after the latest one; a copy while it still says Copied empties it and writes it again in the next frame, so a screen reader announces each copy. It is the last child of `<body>`, and while a dialog is shown it moves to the end of that dialog, since `showModal()` takes the rest of the page out of the accessibility tree. No script sets `role="group"`, which femto styles as its Group component: the Colors grid's families are toolbars, each one Tab stop (criterion 11). Intervals run only while their element is on screen. The typing demo is hand-written (Risks, TypeIt license). No script watches the scroll to style the docs header or the breadcrumb: both are sticky in CSS, each with a permanent bottom border in femto's `--femto-muted-border-color` (the header from lg up; the breadcrumb below lg, at `top: -1px` so that, stuck, it leaves a deep-linked section's chapter label uncovered).
- **CSS.** The site's CSS is flat, unlayered files in `site/assets/css/`, over vendored femto and its responsive-spacings option, and follows femto's color, prefix and never-use rules (criterion 11). Smooth scrolling only under Decision 10's class.
  - The site's own custom properties are named `--site-*`, never `--femto-*`. Each site color is one `light-dark()` pair on `:root`, as femto declares its color tokens, so femto's `color-scheme` on `:root` and on `[data-theme]` elements picks the side and `data-theme` islands work. Unlike femto, the site has no fallback for a browser without `light-dark()`, which every browser in the target has. Site CSS sets femto tokens only on the elements it styles, never on `:root`, and no site stylesheet loads into a shadow root, so it has no `:host` rules.
  - Viewport heights are CSS: `<body>` has `min-height: 100dvh`, the side nav's `max-height` is a `calc()` on `100dvh`, and the color dialog's article takes femto's own `100svh` rule.
  - Code is set in femto's `--femto-font-family-monospace` and headings in femto's font stack, both system fonts. The one web font is Pacifico, for the CSS variables example's heading, subset to that heading's characters, so a changed heading needs a new subset under a new file name, since `_headers` caches fonts for a year: `uvx --from 'fonttools[woff]==4.60.1' pyftsubset <Pacifico v23's latin woff2> --text="<the heading>" --flavor=woff2 --output-file=pacifico-<name>.woff2`.
  - **Without JavaScript**, under `@media (scripting: none)`, the controls that need the site's scripts are hidden: the copy buttons, the header's theme toggle, the docs breadcrumb with its Documentation button, the menu's Close, the Color schemes switcher, Grid's Add and Remove column, Typography's rem switch, the Modal demo, the Colors palette's help, the Theme picker's swatches with the sentence that introduces them (links to `?theme=`, which only the first inline head script applies), `/examples`' theme select and Copy as page buttons, and the homepage's femto switch, theme swatches and typing demo's Pause (the last three by their `hidden` attribute, which `demo.js` removes). Below lg the docs menu is then a static block before the sections. Risks (Without JavaScript) lists what stays.
  - **In print** every page is light, whatever `data-theme` says (`common.css`'s `[data-theme] { color-scheme: light }`; `examples.js` takes `data-theme` off the mockups' hosts while the page prints), and code wraps. The header's nav, the copy buttons, the docs menu and breadcrumb, the Theme picker's swatches with their sentence and its option switches, the Color schemes switcher, Grid's Add and Remove column, Typography's rem switch, the Modal demo, the Colors palette's help, the homepage's call-to-action row, Pause, femto switch and swatches, and `/examples`' theme select and Copy as page buttons are hidden. The Colors palette and the Themes table's dots print their colors (`print-color-adjust`).
- **Text.** The docs describe femto at the vendored commit, with femto's README there as the source of truth (criterion 13). The CSS variables example keeps its Pacifico heading (the owner, 2026-10-31). The Tokens table, the module map and the Elements index are written by hand from femto at the vendored commit, and criterion 13's femto facts hold them to it.
- **Tools.** Every package is pinned to an exact version, the latest on npm when it is added or moved (the owner).
- **Commits.** A Title Case subject under 60 characters, with no body unless the diff cannot explain itself, and no trailers.

## Acceptance criteria

Each criterion is checked mechanically. `uv run tests/static_checks.py` checks 4 to 6, 8, 9, 11 to 14 and the static parts of 15; the browser harness checks 7, 10 and the run-time parts of 15 (tests/README.md).

Criteria 1 to 3 (the Remix site against itself, the parity gates and the divergence registry) were retired with the parity harness (the owner, 2026-11-09). Their record is at `conversion-final`, and `--criteria 1`, `2` or `3` is a usage error.

4. **Packages and Pages configuration.**
   - `package.json` has no `dependencies`, and no optional, peer or bundle dependencies.
   - Its devDependencies are `prismjs`, `wrangler` and the check tools (`eslint`, `@eslint/css`, `html-validate` and `axe-core`), and may add the JS compat lint `eslint-plugin-baseline-js`, `@eslint/js` and `globals`. Each is pinned to an exact version. `wrangler` is there for `npm run dev` and criteria 4 and 6.
   - Its scripts are `build`, `dev`, `vendor` and `lint`, and none runs `wrangler pages deploy` or `publish` (Decision 11).
   - No file in the repository, tracked or to be tracked, turns on a Pages feature Decision 11 leaves out: no `_redirects`, `_routes.json` or `_worker.js` anywhere, and no `functions/` folder at the root, which Pages' build would compile into Functions.
   - `wrangler.jsonc` (Decision 11) is tracked or to be tracked, never ignored, and is the only Wrangler configuration file. It has exactly `name` `femto-style`, `pages_build_output_dir` `dist` and a `compatibility_date` (YYYY-MM-DD), and the pinned wrangler's `pages functions build-env`, which reads it as Pages' build does, reads `dist` from it.
5. **Build output.**
   - `npm run build` run twice gives byte-identical `dist/` trees.
   - `dist/` contains nothing from `partials/` or `docs/sections/`, no `docs/` folder of per-route pages, and no `_redirects`, `_routes.json` or `_worker.js` (Decision 11).
6. **URLs served.** Under `wrangler pages dev dist`:
   - every URL the URL inventory gives 200 answers 200 with no redirect;
   - `/docs/` and `/docs.html` 308 to `/docs`;
   - every old docs route and any other path answers 404 with the `404.html` body, except the Pages-inherent paths in Risks (Cloudflare).
7. **Docs behavior.** The behavior suite passes in Chrome, Firefox and Safari (`uv run tests/run.py behavior --target dist`; Safari through `tests/owner-safari.sh final` and `reduced`). Among its checks:
   - the spy, deep links (with JavaScript off too, in Chrome and Firefox), nav clicks, back, forward and reload on the one page (the `one-page` group);
   - the mobile menu opening and closing, including Escape and focus;
   - the category `<details>` and the breadcrumb's chapter and section following the spy;
   - nav clicks jumping without animation under reduced motion;
   - the picker swapping the theme and updating `?theme=`;
   - an unknown `?theme=` value being ignored;
   - with JavaScript off, in Chrome and Firefox, every focusable element on screen once focused, the controls that need JavaScript in the markup but not rendered, and the docs menu's links working as the browser's own fragment links (`nojs-focus`, `nojs-menu`);
   - `/`, `/docs` and `/examples` printing light, without their screen-only controls, with a stored dark choice and, on `/docs`, a dark OS, and `/docs`' code blocks printing white (`print-light`, `print-light-os-dark`; in Firefox only `/examples`, Risks), and no page wider than the viewport at 320 px (`reflow-320`).
8. **Head.**
   - `docs.html` has its title, description, `og:title`, `og:description`, `og:url` and `rel=canonical` to `https://femto.style/docs`.
   - `sitemap.xml` lists only page URLs.
   - `site/partials/head.html` has exactly two `meta[name=theme-color]`, with media `(prefers-color-scheme: light)` and `(prefers-color-scheme: dark)`, whose content equals, as a color, femto's `--femto-light-background-color` and `--femto-dark-background-color` in `css/tokens/schemes.css` at the vendored commit.
   - `site/site.webmanifest` is valid JSON with `display` `browser`, a non-empty `id` and a non-empty `description`.
   - `site/opengraph.png` is 1200 × 630 by its IHDR, as `og:image:width` and `og:image:height` say, and at most 32 KB (32,000 bytes).
9. **Valid HTML and ids.**
   - `html-validate` passes on every HTML file in `dist/`, under `.htmlvalidate.mjs`: it extends `html-validate:recommended`, and every rule it turns off or changes carries a comment with the reason.
   - No page has a duplicate id.
   - Every section heading's id matches `^[a-z]+(-[a-z]+)?$`. No other heading in `docs.html` has an id.
   - Every side-nav link targets a section id, and every section has exactly one nav link.
   - No radio `name` or `details name` repeats across separate examples.
   - Every link in the Elements index's cells targets a section's h1.
   - On `/examples`, every `section.example` has exactly one closed `<details>` holding `<summary>HTML</summary>` and `div.code` (a copy button and `pre > code.language-html`), and its header exactly one `button[type=button][data-copy-page]`. No `<select multiple>` or `<select size>` in a shadow root there has a preselected option.
   - Nothing inside the Colors grid's `section[data-color-modal]` has `tabindex`, `role` or `aria-label` in the markup (`colors.js` adds them), and the Media section's live `<pre>`s hold a `<code>` with no class and a `<samp>`.
   - Every live `<form>` in `site/` has `method="dialog"`, whose submit does nothing outside a `<dialog>`, so no example form submits even without JavaScript and nothing typed reaches the URL (2026-11-09). Its code sample keeps a plain `<form>`.
10. **Accessibility.** axe-core finds no serious or critical violation on any page, in Chrome and Firefox, light and dark, at 375 and 1300 (`uv run tests/run.py a11y --target dist`).
11. **Lint.**
    - `npm run lint` passes: `@eslint/css` `use-baseline` at `widely` on `site/**/*.css`, and ESLint on `site/**/*.js`. Every exception carries a reason.
    - No file in `site/assets/css/` contains `@layer`, `@scope`, `if(`, `@function`, `@mixin`, `@apply`, `@custom-media` or `@container style(`.
    - No color function uses `from`, and every `color-mix(` uses `in srgb`.
    - No site script sets `role="group"`, and no site markup outside example markup uses it, since femto styles `[role=group]` as its Group component. No stylesheet that more than one page loads has a rule whose selector is a bare `section`, `article` or `footer`.
    - `scroll-behavior: smooth` appears only under Decision 10's class.
12. **Vendored femto.** Every file in `site/vendor/femto/` equals the commit named in its `SOURCE`, byte for byte. When `SOURCE`'s version is a release (no `-`), `SOURCE` names the tag `v<version>`, and its commit is that tag's (Decision 4).
13. **Content.** The docs are true to femto at the vendored commit:
    - **Custom properties.** Every `--femto-*` name in the docs is declared in femto's `dist/femto.css` or `dist/femto.colors.css`; no site-internal token appears.
    - **Files and URLs.** Every femto file path or jsDelivr path (`dist/…`, `css/themes/…`, `css/options/…`) and every module `@import` relative to femto's `css/` names a file in `site/vendor/femto/`. Links to femto's repository point at the vendored commit or tag.
    - **Classes.** Every femto class in example markup, `/examples`' mockups included, is one femto README's "Classes and attributes" lists, or a color utility class `femto.colors.css` declares.
    - **Version.** Every version string matches `SOURCE`.
    - **Package.** On every dist page and script, femto's package is `@leoherzog/femto` (Decision 4) and nothing else, and nothing offers femto as a Composer package.
