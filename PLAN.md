# femto.style

The conversion from Remix is finished. Its record (the phases, the parity harness, the divergence registry, the research and PROMPT.md) is at tag `conversion-final`.

This file is the site's spec: the decisions, the file tree, the URLs, the rules, the acceptance criteria the checks hold, the live risks and the owner's answers. The checks are in `tests/` ([tests/README.md](tests/README.md)).

## Decisions

Decisions 1 to 9 are the owner's, made on 2026-10-30, and the owner approved 10 to 15 the same day. Decision 16 is the owner's of 2026-11-01, 17 of 2026-11-05 and 18 of 2026-11-06. The owner changed Decision 11 on 2026-11-06 and 2026-11-09, and Decision 4 on 2026-11-09. On 2026-11-09 Decisions 17 and 18's lists of the homepage's glyphs were brought up to the reordered features, which changes nothing they decide, and the owner replaced Decision 17's ⚡ with ⇄. On 2026-11-10 the owner changed Decisions 3 (the build strips the comments from the site's own CSS and JavaScript) and 16 (a toggle back to the OS's scheme forgets the choice), and Decision 18's sentence on which module writes the theme toggles was brought up to the code, which changes nothing it decides. On 2026-11-11 the owner reordered the homepage's features again, and Decision 18's places of `{ }` and `</>` were brought up to it, which changes nothing it decides. Later that day the owner's answers to an audit of the site's departures from vanilla femto (Owner answers 6 to 12) changed Decisions 10 (no reduced-motion wrapper), 16 (the toggle and the switcher are femto's own buttons), 17 (the arrows no longer move on hover) and 18 (no enlarged ⤢). On 2026-11-12 the owner replaced Decision 17's ⤢ with ⇱, and put Decision 18's feature icons in the primary color. Decisions 6 and 15 are historical: they governed the conversion. Do not reopen any of them without asking the owner.

## Rules

- **Build.** `<!-- include partials/<file> -->` markers are the only include syntax. `{{title}}`, `{{description}}`, `{{version}}` and `{{commit}}` are the only placeholders. The build fills `{{version}}` and `{{commit}}` from `site/vendor/femto/SOURCE`, so links to femto's files follow a re-vendor. Code blocks hold escaped text only, in `<pre><code class="language-…">` (`html`, `css`, `bash` or `js`, Prism's javascript grammar, since 2026-11-11), with the `<pre>` written exactly `<pre>`, as the build checks. The build highlights them with Prism as one span per run of one kind, classed `tag`, `attr`, `value` or `comment`, with plain text, most punctuation among it, left unwrapped; `picker.js`, `docs.js` and `demo.js` write the same format. `code.css` colors each class with its `--site-code-*` color, and plain text keeps femto's `--femto-code-color` (the owner, 2026-11-12, over owner answer 7). Inline `<code>` in prose has no class, so it is never highlighted. The build ends each docs section with a `<p>` holding its "Edit this section on GitHub" link, written from its id and named ": <the section's h1>" in visually hidden text, and fails on a section file that holds that text. It copies `site/assets/**/*.css` and `*.js` without their comments (Decision 3): Prism's own CSS and JavaScript grammars find them, so a string or a regex is never read as one; each becomes its newlines; only the spaces next to a comment go, and a comment that alone separates two tokens stays; and the build fails on a source file holding U+E000 or U+E001, the characters it marks comments with. `vendor/femto/` and the HTML keep theirs.
- **Markup.** Plain `<a>` links. The site's own links to other origins (prose, header, footer, the edit links, the homepage's and `/examples`' own text) open in the same tab, with no `target` or `rel` (the owner, 2026-11-10); live example markup and its code samples keep what femto's examples have. The docs' cross-references are fragment-only, `href="#<id>"`, so they keep `?theme=` in a new tab and without JavaScript; the footer's links, the Tooltip example's link and the Theme picker's azure swatch keep `/docs#<id>`. The build writes `aria-current="page"` on header and footer links for the page's own path. Ids follow Decisions 7 and 13, icons Decisions 17 and 18. The docs breadcrumb reads "Documentation > <category> > <section>", its last item has `aria-current="location"`, and its Documentation button holds ☰ and a `<span>` label, which docs.css hides visually below 576 px, so the button keeps its name; below 360 px the category is left out.
- **JavaScript.** ES modules with `type="module"`. A widget finds its markup by a `data-` hook on its root, named after what it is and never after an attribute femto's own CSS or JS uses (`data-theme`, `data-tooltip`, `data-placement`), and does nothing when its markup is absent. No global state shared between widgets; the small helpers that modules share (`setAttr`, `capitalize`, `escapeText`) are `site.js` exports, which every module imports by the same URL. One modal helper per dialog. Both dialogs, Modal's demo and the Colors section's color dialog, are true modals (`createModal()`, which always uses `showModal()`): the page behind is inert, and closing returns focus to the opener (the color dialog's to the swatch of the color it shows last). Escape closes it with the animated close, from a document `keydown` listener while it is open, whose `preventDefault()` stops the browser's close request: a dialog's `cancel` event can be canceled only within the page's close-watcher allowance, which the Modal section's two static `<dialog open>` examples use up on `/docs`, so there the cancel would close it at once (2026-11-10). The `cancel` listener takes the browser's other close requests. A click closes it only when it was pressed and released on the overlay itself, so a text selection dragged out of the card leaves it open. A copy button's tooltip is its name ("Copy code" on every code block), and goes back to the button's own tooltip 1 s after its latest copy. The page's one copy status region (`site.js` `announceCopy()`) says "Copied" at every copy, or "Copy failed" when there is no clipboard or the write fails, and empties 1 s after the latest one. The copy button's tooltip says the same, and so does Copy as page's femto `data-tooltip`, which that button has only for the 1 s after its latest copy: its label keeps its text, and `examples.js` gives it an `aria-label` equal to the label, so the tooltip's text never joins its name (the owner, 2026-11-11). A message that repeats the one before it gets a trailing no-break space, every other time, since VoiceOver skips a message equal to the one before (the owner, 2026-11-10), and a copy while the region still says something empties it and writes the message in the next frame, so a screen reader announces each copy. It is the last child of `<body>`, and while a dialog is shown it moves to the end of that dialog, since `showModal()` takes the rest of the page out of the accessibility tree. No script sets `role="group"`, which femto styles as its Group component: the Colors grid's families are toolbars, each one Tab stop, where Left and Right move within the family and wrap, and Home and End go to its ends (criterion 11). Intervals run only while their element is on screen and the page is visible. The typing demo is hand-written (Risks, TypeIt license), and its form is `inert`, so assistive technology and the keyboard skip its changing controls. No script watches the scroll to style the docs header or the breadcrumb: both are sticky in CSS, each on femto's opaque `--femto-background-color`, with no blur (the owner, 2026-11-11), and a permanent bottom border in femto's `--femto-muted-border-color` (the header from lg up, through `docs.css`; the breadcrumb below lg, at `top: -1px` so that, stuck, it leaves a deep-linked section's chapter label uncovered).
- **CSS.** The site's CSS is flat, unlayered files in `site/assets/css/`, over vendored femto, and follows femto's color, prefix and never-use rules (criterion 11). Only `/docs` also loads femto's responsive-spacings option (Decision 8); `/`, `/examples` and 404 load femto alone (the owner, 2026-11-11). Smooth scrolling only under Decision 10's class. Every page links `common.css`, and every page but 404 also `code.css` and its own stylesheet, never another page's (criterion 8): `/examples` no longer loads `landing.css` (the owner, 2026-11-10), and neither page has a spacing scale of its own: both take femto's main padding and section margins (the owner, 2026-11-11).
  - **femto's defaults.** "Default to femto upstream defaults wherever possible" (the owner, 2026-11-10). Where the site can either set a value (a size, spacing, color, radius, typography or a component's styling) or take femto's, it takes femto's, by having no override, or derives the value from femto's tokens (`--site-header-height`, which `docs.css` reads, is the docs header's height summed from femto's spacing, nav and line-height tokens). An override stays only for a functional need, a Decision or Rule, or a check that asserts it: the icons (Decisions 17 and 18), Decision 10's smooth scrolling, the sticky header and breadcrumb, the docs grid and off-canvas menu, the print and no-JavaScript hiding, the layout the pages need, the widgets femto has no styling for (the copy buttons, the typing demo, which draws femto's own focus styles with femto's tokens, the Theme picker's swatches and the Colors palette with its dialog), the frames that keep the homepage's femto off and on block and `/examples`' mockups apart from the page, the logo's brand colors and hover sparkle, and the four colors of highlighted code, which the owner kept over femto's one code color (2026-11-12). The header is femto's nav, the logo its first list, and the docs header from lg is opaque in `--femto-background-color` (the owner, 2026-11-11). No site font size is in px, so all text follows the reader's default font size, and code takes femto's 0.875em (the owner, 2026-11-10), except the homepage hero's one-line link snippet, at 0.68em from 1024 to 1279 px, in femto's 950px container, so that it fits without scrolling; from 1280 px it fits at femto's size (the owner, 2026-11-11). A change femto needs goes to femto, never into `site/vendor/femto/` (criterion 12).
  - The site's own custom properties are named `--site-*`, never `--femto-*`. Its own colors are femto's brand colors on the logo, `--site-logo-wordmark` and `--site-logo-sparkle`, and the four colors of highlighted code, `--site-code-tag`, `--site-code-attr`, `--site-code-value` and `--site-code-comment`, each at least 4.5:1 on femto's code background and card sectioning background in both schemes, and no other: the header's background and the footer's quieter sparkle went on 2026-11-11, and the code colors, gone that day, came back on 2026-11-12 (the owner); `demo.js`'s `--site-swatch` only carries each theme's femto color to its swatch. Each site color is one `light-dark()` pair on `:root`, as femto declares its color tokens, so femto's `color-scheme` on `:root` and on `[data-theme]` elements picks the side and `data-theme` islands work. Unlike femto, the site has no fallback for a browser without `light-dark()`, which every browser in the target has. Site CSS sets femto tokens only on the elements it styles, never on `:root`, and no site stylesheet loads into a shadow root, so it has no `:host` rules.
  - Viewport heights are CSS: `<body>` has `min-height: 100dvh`, the side nav's `max-height` is a `calc()` on `100dvh`, and the color dialog's article takes femto's own `100svh` rule.
  - Code is set in femto's `--femto-font-family-monospace` and headings in femto's font stack, both system fonts. The one web font is Pacifico, for the CSS variables example's heading, its `@font-face` at the top of `docs.css`, subset to that heading's characters, so a changed heading needs a new subset under a new file name, since `_headers` caches fonts for a year: `uvx --from 'fonttools[woff]==4.60.1' pyftsubset <Pacifico v23's latin woff2> --text="<the heading>" --flavor=woff2 --output-file=pacifico-<name>.woff2`.
  - **Without JavaScript**, under `@media (scripting: none)`, the controls that need the site's scripts are hidden: the copy buttons, the header's theme toggle, the docs breadcrumb with its Documentation button, the menu's Close, the Color schemes switcher, Grid's Add and Remove column, Typography's rem switch, the Modal demo, the Colors palette's help, the Theme picker's swatches with the sentence that introduces them (links to `?theme=`, which only the first inline head script applies), `/examples`' theme select and Copy as page buttons, and the homepage's femto switch, theme swatches and typing demo's Pause (the last three by their `hidden` attribute, which `demo.js` removes). Below lg the docs menu is then a static block before the sections. Risks (Without JavaScript) lists what stays.
  - **In print** every page is light, whatever `data-theme` says (`common.css`'s `[data-theme] { color-scheme: light }`; `examples.js` takes `data-theme` off the mockups' hosts while the page prints), and code wraps. The header's links and theme toggle (its nav's last list; the logo prints), the copy buttons, the docs menu and breadcrumb, the Theme picker's swatches with their sentence and its option switches, the Color schemes switcher, Grid's Add and Remove column, Typography's rem switch, the Modal demo, the Colors palette's help, the homepage's call-to-action row, Pause, femto switch and swatches, and `/examples`' theme select and Copy as page buttons are hidden.
